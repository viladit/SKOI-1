## 1. Теоретическая база

Chroma key заменяет выбранные по цвету пиксели первого изображения пикселями второго с теми же координатами. Остальные пиксели сохраняются.

Цвет RGB состоит из красного R, зелёного G и синего B. Каждый канал принимает значения от 0 до 255. Пользователь задаёт нижнюю и верхнюю границы. Пиксель заменяется, только если все три канала попадают в свои интервалы. Границы включены.

Для демонстрации выбран такой диапазон.

```text
0   <= R <= 135
140 <= G <= 255
0   <= B <= 145
```

Например, `(50, 200, 70)` заменяется, а `(50, 200, 180)` сохраняется, поскольку значение B превышает 145. Время и дополнительная память алгоритма составляют O(N), где N обозначает число пикселей.

## 2. Описание системы и запуск

Весь код находится в `main.py`. Собственная функция `chroma_key_python` сравнивает и копирует каналы явными циклами. Функция `chroma_key_opencv` использует `inRange` для маски и побитовые операции для объединения изображений. В режиме `both` результаты сравниваются по всем пикселям.

Изображения должны иметь одинаковые размеры. Цветовые файлы приводятся к RGB uint8, прозрачность отбрасывается. Исходные изображения не изменяются. Для сохранения без потерь используется PNG.

В PyCharm открыть папку `lab1`, выбрать её интерпретатор `.venv/bin/python` и выполнить Run для `main.py`. Без аргументов программа использует картинки из `data` и сохраняет `results/result.png`. На этом компьютере окружение уже подготовлено.

Установка зависимостей и запуск из терминала проекта.

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

Свои изображения и диапазон можно передать аргументами.

```bash
.venv/bin/python main.py --foreground data/foreground.png --background data/background.png --lower 0 140 0 --upper 135 255 145 --method both --output results/result.png
```

Для отдельной реализации доступны `--method python` и `--method opencv`. Для повторения замеров и построения графиков выполнить следующую команду либо указать `--report` в поле Parameters конфигурации PyCharm.

```bash
.venv/bin/python main.py --report
```

Узкий интервал оставляет часть зелёного фона. Слишком широкий захватывает одежду и волосы. Сравнение трёх интервалов показано ниже.

Проверены включённые границы, порядок RGB, полная и нулевая замена, ошибочные входы, сохранность оригиналов и равенство двух реализаций. На демонстрационной фотографии результаты также совпадают.

Замеры выполнены 20.10.2026 на Apple M4 Pro под macOS 26.6.1. Использованы Python 3.14.5, NumPy 2.5.4 и OpenCV 5.0.0. Для каждого размера подготовлены одинаковые случайные массивы с seed 368925 и диапазоном `(0, 150, 0)` - `(100, 255, 100)`.

После двух прогревов проведено 10 замеров с чередованием порядка реализаций. Время измеряется через `perf_counter`, включая проверки и выделение массивов внутри ядра. Чтение, сохранение и подготовка данных исключены. Быстрые вызовы OpenCV измеряются пачками с пересчётом на один вызов. Ниже приведены медианы.

| --- | --- | --- | --- |
| 320 x 240 | 0.082 | 44.301 | 539.2 |
| 640 x 480 | 0.309 | 179.334 | 581.1 |
| 1280 x 960 | 1.212 | 713.955 | 589.0 |

На графике логарифмическая шкала времени, усы показывают минимум и максимум. Полные замеры сохранены в [benchmark.json](results/benchmark.json). Ускорение равно отношению медианы Python к медиане OpenCV.

## 4. Выводы

Обе реализации дают одинаковый результат. OpenCV существенно быстрее благодаря обработке массивов в библиотечном коде. Время обработки растёт примерно пропорционально числу пикселей.

Качество зависит от диапазона. Алгоритм различает только цвета, поэтому может оставить тени и зелёные отражения или удалить части объекта. Сглаживание границ и распознавание объектов в эту работу не входят.
